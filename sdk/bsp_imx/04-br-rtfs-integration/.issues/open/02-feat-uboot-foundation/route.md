# 实施路线

2026-10-13：当前交付为需求与技术路线对齐，源码迁移和实现尚未完成。行为与验收见 [issue.md](issue.md)，技术约束见 [adr.md](adr.md)，失败快照中的机制与迁入限制见 [实现参考.md](实现参考.md)。

## R1 · 固定输入与固件能力

在隔离 worktree 中建立 `uuf/` 产品源码，迁入 02 的固定 U-Boot 板级输入和构建入口。补齐 ROM USB 自动 fastboot、boot0 产品启动、extlinux 发现、3 秒控制台打断和 ext4 文件写入。

先完成配置与轻量编译检查，再交付完整构建命令给开发者执行，默认 `-j12`。使用 03 的真实 kernel/DTB 检查下载缓冲区与内存范围，并验证 kernel ext4 的单文件覆盖及未选内容保留。

出口：固件输入可复现，ext4 独立覆盖路线可用；真实板卡证据由开发者提供。能力不满足目标时先对齐方案。

## R2 · 制像、归档与主机 CLI

按真实载荷及预留量生成最终 MBR，以其为唯一分区几何来源；清单维护组件到 MBR 表项的映射，固件部署描述和启动描述保持独立。生成 kernel 分区与 rtfs 分区 Sparse，完成归档打包/解包、直接选择归档的一键部署和各组件独立更新入口。

共用主机预检、只读目标探测、范围计划、正式确认、UUU 执行、固件 hash 门控及写后验证。基础探测支持空盘；布局更新同时重建并部署两个 ext4 与匹配 MBR。主机 `--dry-run` 不下载 loader、不写板。

出口：主机检查及 UUU dry-run 通过，开发者可审阅完整操作文档。验证 Sparse 有效块、文件覆盖与未选内容保留，不把主机测试当成实板验收。

## R3 · Tauri/React GUI

GUI 调用同一后端，按“烧录／镜像准备／设备信息”提供输入选择、MBR 分区表编辑、制像与归档、实际分区与镜像信息、操作计划、确认、进度及错误结果。采用米白底与橙棕强调，按屏幕中心约 1/4 面积设置初始窗口。

出口：GUI 与 CLI 生成相同目标和范围，组件选择与实际计划一致，错误与断连停止后续操作，取消后完成子进程清理。

## R4 · 板卡验收与 BR 消费接入

由开发者以 03 BusyBox 载荷验证一键部署、boot0 冷启动、全部组件独立替换、指定范围擦除、固件免重复擦写及启动配置修改。验证布局变更必须伴随匹配镜像。

之后由 issue 01 接入真实 BR 系统，独立验收 systemd 冷启动。完整构建与硬件写操作交由开发者执行；全部判据通过后归档 issue。
