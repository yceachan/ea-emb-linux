# 02 · i.MX6ULL 通用 UUU/U-Boot 基础层

状态：需求范围已由用户确认，细化讨论进行中，尚未按新需求完成实现。本文是 U-Boot 基础层的需求与验收来源；接口、布局及实现方案的未决项见 [discussion.md](discussion.md)，事实进度见 [progress.md](progress.md)。父级 [BR 系统 issue](../01-feat-br-system/issue.md) 消费本基础层，不决定它的项目输入或路径。

## 1. 用户确认与适用范围

用户确认上一轮完整需求稿的前七条，随后明确以下四项：

> 1. 只适配这个 imx6ull 板卡。
> 2. MBR + ext4。
> 3. 就用。
> 4. 更新产品 uboot，但验算 target hash，一致就不必做累赘擦写。

第 3 项对应“一份整盘 Sparse＋外部布局／启动描述”的方案，不要求 Sparse 单文件自行辨识全部组件。当前板卡是 100ask i.MX6ULL Pro；不扩展到其他板卡、SoC、存储平台或 GPT。文件系统采用 ext4，不再把旧 FAT32 启动分区当作实施前提。分区数量、编号、起点、容量及组件位置仍需细化，不由现有代码倒推。

“通用”指同一板卡上可服务不同 Linux 项目。板卡 DDR、UART、USB、eMMC 适配保留；BusyBox、Buildroot、systemd 和业务系统均是外部消费者。03 BusyBox 可作为验收案例，其版本、归档 hash 和目录不得成为基础层默认依赖。

## 2. 固件、工具与项目的职责

固件提供硬件初始化、ROM 下载后自动进入 UUU/fastboot、存储查询与读写、Sparse 写入、启动文件操作及标准启动配置加载。普通启动使用项目提供的启动配置，不内嵌 Linux kernel/DTB 文件名、root 参数、PID 1 或用户空间版本。RAM loader 与产品 bootloader 两个角色都须有明确入口；是否用同一个二进制由实现方案说明，不凭名称判断适用性。

主机工具消费调用者给出的固件、布局、启动配置和组件产物，完成镜像、更新、检查、计划与证据处理。本轮不负责构建 kernel、DTB、rtfs 或业务系统，不以完整项目包作为独立操作的前提。

项目负责生成自己的 Linux 产物、决定布局和启动参数，并提供验收配置。U-Boot 源码、工具链和板级输入仍需记录可复现身份；这不等于给项目产物固定版本或 hash。

## 3. 必需能力

| 编号 | 能力与约束 |
|---|---|
| U1 硬件与启动 | 仅适配当前板卡。支持 ROM USB 下载后自动进入下载服务，以及从 eMMC 按外部启动配置启动；无需开发者逐条输入 fastboot/boot 命令。 |
| U2 路径与描述 | 主机源码、工具链、构建、固件、组件、输出及日志路径由参数或环境提供，不要求固定仓库位置或 CWD。设备、硬件区域、分区几何及镜像内文件路径由板卡／外部布局和启动描述提供。源码继续维护在 04/uboot/，不将该位置变成工具运行条件。 |
| U3 合成整盘 Sparse | 消费 MBR/ext4 布局、外部启动配置、kernel、DTB 和 rtfs Sparse，输出一份整盘系统 Sparse；不要求 U-Boot 构建或 BR/BusyBox 项目包参与纯镜像操作。 |
| U4 整盘部署 | 消费固件、整盘 Sparse 及外部描述，一次主机入口完成 RAM loader、整盘系统写入、产品 U-Boot 更新与必要启动设置。系统数据阶段只发送整盘 Sparse，不分别发送 kernel、DTB、rtfs。产品 U-Boot 位于独立硬件区域时，另按明确映射操作，不能伪称这些区域属于同一 Sparse 地址空间。 |
| U5 独立板卡更新 | 直接消费 kernel、DTB 或 rtfs Sparse 以及目标描述，只更新指定组件；不要求其他组件输入或重新制作完整包。保留未选组件、分区表、bootloader 和启动配置。 |
| U6 修改已有 Sparse | 消费已有整盘 Sparse、新 kernel/DTB/rtfs Sparse 及组件定位信息，输出新 Sparse，默认不覆盖原镜像。只修改所选内容与必要元数据，保留未选组件的数据和稀疏写入／跳过语义。 |
| U7 独立固件部署 | 提供仅部署产品 U-Boot 的入口，不依赖系统镜像；包含目标、启动配置、读回与冷启动验证规则。不得以整盘烧录代替独立固件部署。 |
| U8 检查与计划 | 检查输入格式、容量、布局、写入范围和组件定位；信息不足或有多个候选时要求明确选择，不猜测固定文件名或分区。source 文件名不决定 target 文件名。 |
| U9 安全与验证 | dry-run 只检查主机输入与计划，不下载、不写板；正式操作仍先预检，再展示目标和范围并二次确认。实际 loader 启动后、持久写入前复核真实设备信息与布局，写后核验。错误、断连和比较失败停止后续操作，不自动回滚。 |
| U10 构建与交付 | 耗时 SDK 构建交给开发者，默认 -j12；代理不执行真实硬件写操作。交付可复现输入、完整操作文档和分层证据，不用主机测试替代实板验收。 |

U4、U7 均包含第 4 节的产品 U-Boot hash 门控。U5 不擅自更新产品 U-Boot，不将整盘入口的行为推广到组件入口。

## 4. 产品 U-Boot：先验算 target，再决定更新

比较必须基于本轮实际目标区域读回，不能使用旧日志或缓存 hash。输入镜像与目标比较的字节范围、偏移、长度和填充规则必须一致；具体规则由后续讨论锁定。

| 本轮目标比较 | 必须行为 |
|---|---|
| target hash 与输入一致 | 记录比较范围、hash 和 skipped 结果；不对产品 U-Boot 镜像区域重复擦除或写入。 |
| target hash 与输入不同 | 在已预检和确认的范围内更新产品 U-Boot；写后重新读回并比较，成功后才继续／完成。不同不等于必须先做全区域擦除。 |
| 读回失败、范围不明或 hash 无法可靠获得 | 判为失败并停止；不得把“无法比较”当成“不同”而直接写入。 |

镜像相同与启动配置正确是两个条件。镜像相同不代表 eMMC 启动设置已正确；应独立检查必要启动设置，错误时修正并记录，不能用镜像 skipped 代替完整部署判定。启动配置的具体比较／修正规则仍待细化。

## 5. 保留与 Sparse 语义

kernel/DTB 文件更新允许修改必要的 ext4 元数据，但不能顺带改启动参数或其他文件内容。rtfs Sparse 的写入范围须限制在描述指定的区域，不自动扩大分区或修改 MBR。

主机修改已有 Sparse 时，未选区域的数据和 RAW/FILL/DONT_CARE 写入语义均需保留。不能以重新生成整个项目镜像代替局部替换，也不能把已分配的零数据猜作空闲块而改成 DONT_CARE。

DONT_CARE 保留介质已有内容，不是安全擦除。写后验证覆盖实际写入的数据范围；不能把展开镜像中的零值用于证明被跳过介质也为零。支持的 ext4 特性及其元数据检查能力必须明确，不承诺未经验证的特性组合。

## 6. 验收条件

| 编号 | 判据 |
|---|---|
| UA1 解耦与路径 | 至少两组不同项目名称／文件名／主机工作目录的输入通过同一基础入口；核心不读取固定 03/BR 目录、版本或产物 hash。硬件适配仍限定当前板卡。 |
| UA2 MBR/ext4 | 以外部描述建立和检查 MBR/ext4，验证分区几何、启动文件及支持的 ext4 特性；不沿用 FAT32 操作冒充新实现。 |
| UA3 合成与整盘烧录 | kernel、DTB、rtfs Sparse 合成单份整盘 Sparse；有效块和跳过范围可核验。实板完成 ROM→loader→下载服务、整盘写入／读回及独立 eMMC 自动冷启动。 |
| UA4 独立更新 | 分别只提供 kernel、DTB、rtfs Sparse 执行板卡更新；指定内容正确，未选组件、MBR、产品 U-Boot 与启动配置保持不变，每种更新后启动预期系统。 |
| UA5 已有镜像替换 | 对同一已有 Sparse 分别替换三个组件；原镜像保持原内容，输出镜像结构正确，未选内容和稀疏写入范围不变，必要 ext4 元数据一致。 |
| UA6 固件 hash 门控 | 覆盖一致、不同、读取失败及“镜像一致但启动配置错误”四类情况。实板一致路径证明没有产品镜像区域擦写；不同路径写后 target hash 与输入一致。 |
| UA7 安全与证据 | dry-run 无下载／硬件写入，正式入口预检及确认不可绕过；失败无虚假成功。记录输入、目标、范围、hash、实际写入／跳过结果和完整运行证据，区分主机与实板结论。 |
| UA8 完整交付 | 文档以一套一致的变量／输入角色说明构建、合成、整盘烧录、独立组件烧录、已有 Sparse 替换及固件部署；示例明确哪些命令真实可用，不拿提议 CLI 当成现有实现。 |

03 BusyBox 的使用只计作一个外部验收案例，不要求其成为固件或工具内置模式。BR/systemd 的父级验收另行完成。

## 7. 状态与来源约束

先细化外部描述、ext4 分区组织、文件替换能力与 target hash 比较规则，再确定接口和实施顺序。未决问题必须有明确决定，不边写实现边把猜测固化成接口。

此前 FAT32、固定容量、固定路径和 BusyBox 专用入口属于历史实现，不能据其测试宣称满足本专章。历史产物和证据保留，但不转换为新范围的通过结论。当前 issue 保持 open，不执行新固件／镜像构建或板卡写操作。
