# 02 · uuf 与 i.MX6ULL UUU RAM loader 基线

本轮修订明确归档中的分区几何与组件映射。需求以本文为准，技术决策见 [adr.md](adr.md)。原始 issue 与早期 ADR 可从 `be749c6` 追溯；失败结论见 [未对齐记录与失败实现.md](未对齐记录与失败实现.md)。

## 1. UUU RAM loader

基于 02工程的板卡 DDR、UART、USB、eMMC，fastboot 基线迭代开发。

将本项目的uboot基线配合现有uuu version ，在host上提供对Linux 和RTFS镜像的一键烧录能力。

将 `04/uuf/` 作为适配当前 i.MX6ULL 板卡的烧录工具工作区。CLI 名称为 `uuf`，GUI 使用 Tauri／React，随附板级 U-Boot 固件基线。初始窗口位于屏幕中心、约四分之一面积。

GUI 使用米白底、橙棕强调色，按“烧录／镜像准备／设备信息”组织功能。烧录页提供完整系统与组件更新；镜像准备保留布局编辑、制像、打包与解包。设备信息页展示分区信息。执行区显示状态和日志。

能力矩阵：

| U1 硬件与启动         | 仅适配当前板卡。支持 ROM USB 下载后自动进入下载服务          |
| --------------------- | ------------------------------------------------------------ |
| U2 路径与描述         | 主机源码、工具链、构建、固件、组件、输出及日志路径由参数或shell变量提供，不要求固定仓库位置或 CWD。设备、硬件区域、分区信息及镜像内文件路径由板卡／外部布局和启动描述提供。源码维护在 04/uuf/。 |
| U3 eMMC layout | 产品 U-Boot 裸写 boot0；user area 使用 MBR，包含 kernel、rtfs 两个 ext4 分区。kernel 分区保存 kernel、DTB 和 extlinux。支持单独和组合更新 U-Boot、kernel、DTB、rtfs。 |
| U4 sparse             | ext4文件系统，打包成aosp sparse镜像烧录，避免累赘写零。      |

## 2. 产品 U-Boot

本uboot 固件复用为实际烧录到emmc 的固件，当从emmc启动固件时，去引导内核。

启用发行版启动机制，通过 extlinux.conf 配置启动选项。启动描述独立于分区几何和固件部署描述。

启动wait 3s ，任意键进入uboot 控制台。

bootmenu 后续支持从板载rtfs / 网络rtfs 启动，以此对齐USB_ECM。先保留扩展点,到时候从板载rtfs进去，在发行版配置网络rtfs启动项。

## 3. 归档中的分区几何

归档携带最终 `mbr.bin` 与按该布局制作的 kernel、rtfs 两张 ext4 Sparse。MBR 决定磁盘 signature、分区表项、起点、长度、类型和活动标志。

清单显式关联镜像与 MBR 表项，区分 kernel／rtfs 角色，不从镜像文件名猜测目标。U-Boot 的 boot0 写入范围与启动设置由固件部署描述给出，不纳入 user area 分区表。

镜像准备按 MBR 分区容量制作两个新 ext4，kernel 分区内的启动配置须正确引用 rtfs。改动布局后，两张镜像与启动引用一起重新检查，不能仅替换归档中的 MBR。

烧录前读取实际设备容量，核对分区不重叠、不越界，以及 Sparse 逻辑长度与对应分区容量匹配。计划区分源文件大小、分区容量与写入范围。较大的 eMMC 不自动扩展归档布局；容量不足则拒绝。

## 4. 验收条件

以本产品 U-Boot、03 的 kernel／DTB 与 BusyBox rtfs 制作归档，通过 RAM loader 部署 eMMC 并冷启动。验证各组件独立替换，以及明确固件范围或完整分区的擦除；。在 BusyBox 中修改 extlinux 启动项，此后默认引导该 BusyBox。


核对归档 MBR 与部署后的分区表一致，组件目标映射无歧义。完整归档部署不依赖额外的 JSON profile，也不要求用户先手工解包。

布局更新必须有匹配的两张新 ext4 镜像；缺少任一镜像时拒绝。重建后旧文件系统不可达，不以物理清零作为验收条件。启动配置独立修改不属于布局更新。

首次空盘探测能返回 CID、容量和原始分区表状态。GUI 显示的组件、目标范围与实际计划一致；取消操作须完成子进程清理，不能仅以界面状态判定停止。
